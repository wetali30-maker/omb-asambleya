# SPEC.md — «Асамблея ОМБ» v2 (онлайн-RP)

Ролевая веб-платформа для военно-политической игры: общий зал, чат и личные
сообщения, очередь выступлений, резолюции и голосования, документы и архив.

> **Статус документа.** Это целевая спецификация версии 2 (онлайн). В
> репозитории сейчас находится версия 1 — локальный однопользовательский
> прототип, проверенный в браузере. Пункты v2 ещё **не реализованы**; работа
> начнётся только после подтверждения владельца. Ничего не публиковалось и не
> деплоилось.
>
> **Главный приоритет:** общение. Чат, шёпот и запрос слова — основные функции.
> Любое решение по интерфейсу, архитектуре и правам должно ускорять и упрощать
> общение, а не мешать ему. Управление, документы и декор — вторичны.

---

## 0. Границы и ключевые решения

| Вопрос | Решение v2 |
|---|---|
| Хостинг фронтенда | GitHub Pages: только статические `/index.html`, `/css`, `/js`, `/assets`, `/vendor`, `/config.public.js`, `/docs` |
| Бэкенд | Supabase: Postgres + Auth + Realtime + Storage + Edge Functions |
| Секреты | Только на сервере: хэши паролей, список администраторов, service-ключи. Во фронтенде секретов нет |
| Регистрация | Логин + пароль, без Google и без обязательной почты |
| Роли | Администратор (ровно 3), председатель, дипломат, наблюдатель |
| Пароль президиума | Один общий пароль председателей; хранится только как bcrypt-хэш; нигде не отображается |
| Чат | Главная функция: общий канал + шёпот, отдельная вкладка на телефоне, realtime |
| Мобильные | Полноценная версия 360–480 px, нижняя навигация, крупные действия, без «урезанного ПК» |
| Офлайн | Онлайн-режим требует сети. Автономный HTML-файл остаётся только демо-превью интерфейса |

**Почему нужен бэкенд.** GitHub Pages отдаёт только файлы: он не умеет хранить
пользователей, проверять пароли, разграничивать доступ и синхронизировать чат.
Скрывать пароль или список админов в JS бессмысленно — исходники доступны
любому. Поэтому безопасность и совместная работа выносятся в Supabase; фронтенд
остаётся статическим и готовым к GitHub Pages.

**Что было в v1.** Локальное состояние в `localStorage`, шесть цифр «кода
администратора» на экране, один браузер на всех, чат без сети. В v2 видимый код
администратора удаляется полностью; его заменяют аккаунты, роли и серверные
проверки.

## 1. Концепция и атмосфера

- Сеттинг: холодная война, канцелярия международной организации, делопроизводство
  1980-х: тёмное дерево, бумажные папки, штампы, печатная машинка, латунь,
  приглушённый свет.
- Палитра: тёмный кофейный, серо-коричневый, пыльный беж, приглушённые бордо,
  олива, охра, пыльный синий. Без ярких и неоновых цветов.
- Типографика: PT Mono — документы, номера, таймер; Oswald — заголовки и капс;
  системный гротеск — интерфейс и чат.
- Изображения локальные (`images/`, `assets/`), без внешних CDN в интерфейсе.
  Сетевые запросы v2 идут только к Supabase (данные и чат).
- Атмосфера не должна мешать чтению: фактуры остаются фоном, текст и элементы
  управления — на чистых контрастных поверхностях.

## 2. Загрузочный экран и первый запуск

### 2.1 Загрузочный экран

- Полноэкранный оверлей поверх приложения при каждом холодном запуске и
  восстановлении сессии.
- В центре — вращающийся контурный глобус: SVG-сетка меридианов и параллелей,
  латунные линии, лёгкое свечение; вращение CSS, без WebGL и внешних библиотек.
- Текст: «АСАМБЛЕЯ ОМБ» и ниже «заседание открывается…». Дополнительно —
  состояние подключения: «проверяем связь», «синхронизация зала».
- Минимальная длительность показа — 700 мс, чтобы не было мигания; скрывается
  после готовности сессии и первого рендера. Если сервер не ответил за 8 секунд —
  сообщение «нет связи» и кнопка «Повторить».
- При `prefers-reduced-motion: reduce` глобус статичен, без вращения.
- Загрузчик не раскрывает никаких кодов, паролей и административных данных.

### 2.2 Первый вход и обучение

- Новый пользователь проходит регистрацию/вход, затем короткий онбординг
  (не более 4 подсказок): «Сесть на место», «Написать в чат», «Выдвинуть
  резолюцию», «Голосовать». Подсказки можно пропустить; повторно не показываются.
- На первом экране — только основные действия. Вторичные (архив, журнал,
  настройки, помощь, выход) убраны в меню «Ещё».
- Приветственное окно v1 с кодом администратора удаляется. Никаких подсказок о
  пароле президиума или админ-панели на сайте нет.

## 3. Каркас, адаптивность и мобильная версия

### 3.1 Общий каркас

- Верхняя шапка: эмблема, название заседания, состояние связи, профиль,
  уведомления, «Ещё».
- Центр: зал (SVG, вид сверху) с масштабированием под экран.
- Панели: чат/шёпот, резолюции, журнал; на широком экране — справа, на узком —
  шторки.
- Нижняя строка: на десктопе — тикер и статус; на телефоне — навигация.
- Основная панель быстрых действий: «Сесть на место», «Написать», «Резолюция»,
  «Голосовать». Кнопки появляются по контексту и всегда доступны с телефона.

### 3.2 Мобильная версия (360–480 px) — обязательная

- **Нижняя навигация** (bottom bar) с четырьмя разделами: «Зал», «Чат»,
  «Резолюции», «Ещё». Высота не меньше 56 px, учтён `safe-area-inset-bottom`.
- **Чат — отдельная вкладка**, а не спрятанная панель. Внутри — переключатель
  «Канал / Шёпот», список диалогов и закреплённое поле ввода. Клавиатура не
  перекрывает поле ввода (учёт `visualViewport`), страница не «прыгает».
- Счётчик непрочитанных сообщений на иконке «Чат» и на «Шёпот».
- Боковые панели на телефоне — шторки на весь экран с крупной кнопкой закрытия;
  модалки — полноэкранные или нижние листы.
- Зал всегда вписывается по ширине; зум и перетаскивание не обязательны для
  посадки. Нажатие на свободное место открывает крупную кнопку «Сесть».
- Минимальный размер интерактивной зоны — 44×44 px; основной текст — не меньше
  14 px; имена председателей — 16–18 px.
- Доступны все функции: посадка, чат, шёпот, резолюции, голосование, слово,
  протокол, архив. Никаких «только на ПК».
- Проверка: 360, 390, 414, 480 px в портретной и ландшафтной ориентации; iPhone
  с вырезом; Android Chrome; экранная клавиатура.

### 3.3 Десктоп

- Панели остаются, но шапка упрощается: основные действия видны, второстепенные —
  в «Ещё». Убираются дублирующие кнопки.
- Чат остаётся всегда открытым справа; на широком экране — не уже 360 px.

## 4. Доступ, аккаунты и безопасность

### 4.1 Модель угроз и граница доверия

- Весь фронтенд публичен. Любой может прочитать JS, `config.public.js` и
  сетевые запросы. Поэтому клиент не считается доверенным.
- **Секреты никогда не попадают во фронтенд:** ни пароли, ни их хэши, ни список
  администраторов, ни `service_role`, ни ключи БД.
- Публичными могут быть только URL Supabase и anon/publishable key. Это не
  секреты: доступ ограничивается Row Level Security (RLS) и серверными
  функциями.
- Любая роль, проверенная в интерфейсе, — только UX. Каждое действие повторно
  проверяется на сервере.
- Серверные функции аудируются: кто, что, когда и над кем сделал.
- XSS-защита: пользовательский текст выводится только как текст, без вставки
  HTML; CSP запрещает сторонние скрипты; загружаемые файлы проверяются по типу и
  размеру.

### 4.2 Регистрация и вход

- Только логин и пароль. Без Google, без обязательной почты, без SMS.
- Логин: 3–24 символа (буквы, цифры, `_`), уникален без учёта регистра.
- Пароль: не короче 8 символов; поле с показом/скрытием; понятные ошибки;
  ограничение попыток.
- Внутри Supabase Auth создаётся техническая учётная запись с детерминированным
  служебным адресом вида `<hash(username)>@omb.invalid`. Пользователь почту не
  видит и не вводит.
- Регистрация выполняется серверной функцией (Edge Function) атомарно: проверка
  логина, создание пользователя, создание профиля. Пароль хэшируется средствами
  Supabase Auth (bcrypt), в БД и фронтенде открытого пароля нет.
- Пользователь может сменить свой пароль в профиле. Восстановление без почты —
  через администратора: временный пароль выдаётся вне сайта, после входа
  пользователь обязан его сменить.
- Сессия переживает перезагрузку; есть явный «Выйти» на всех устройствах.
- Интерфейс регистрации — одна колонка, крупные поля, корректная работа с
  мобильной клавиатурой.

### 4.3 Роли

| Уровень | Роль | Кто это | Основные права |
|---|---|---|---|
| 1 | Администратор | ровно 3 аккаунта из защищённого списка | Всё, что делают председатели, плюс админ-панель; может играть как обычный игрок |
| 2 | Председатель | аккаунт, назначенный в президиум | Управление заседанием, слово, голосования, протокол, модерация зала |
| 3 | Дипломат | участник с правом голоса | Чат, шёпот, слово, резолюции, голос |
| 4 | Наблюдатель | участник без голоса | Чат, шёпот, присутствие; без слова, резолюций и голоса |

- **Роль аккаунта** (`admin` / `player`) отделена от **роли в заседании**
  (`chairman` / `delegate` / `observer`). Администратор может сидеть как
  дипломат или наблюдатель и пользоваться админ-панелью отдельно.
- Председательство — должность поверх делегации, а не отдельный тип участника.
- Один аккаунт — одна персона в заседании. Переключение чужих персонажей
  невозможно.
- Смена роли в заседании — только председателем (в рамках регламента) или
  администратором; глобальный бан — только администратором.

### 4.4 Пароль президиума

- Существует один общий пароль для председателей. Он известен только
  председателям и администраторам и **нигде на сайте не отображается и не
  подсказывается**.
- В репозитории, SPEC, JS, HTML, логах и сообщениях пароль в открытом виде не
  хранится. При первичной настройке он один раз вводится в защищённую консоль
  или переменную окружения и сразу превращается в bcrypt-хэш (cost 12).
- Хэш лежит в приватной серверной таблице, недоступной клиенту. Проверка —
  только серверной функцией.
- Назначение в президиум делает администратор. После назначения аккаунт видит
  кнопку «Пульт президиума», но при первом открытии должен ввести пароль
  президиума. Успешная проверка выдаёт разблокировку на 8 часов (или до выхода);
  все управляющие действия проверяют её на сервере.
- Ошибки: не более 5 попыток за 10 минут на пользователя, затем временная
  блокировка. Все попытки аудируются без записи введённого пароля.
- Смена пароля — только в админ-панели: администратор вводит новый пароль и
  подтверждение; после сохранения все прежние разблокировки аннулируются, новый
  пароль передаётся председателям вне сайта.
- Администраторы выше этого пароля и не нуждаются в нём.
- Пароль из брифа владельца в этом документе намеренно не приводится.

### 4.5 Администраторы

- Администраторов ровно **три**. Список хранится на сервере в приватной таблице
  (`admin_allowlist`) в виде идентификаторов пользователей; клиент его не
  получает.
- Список задаётся владельцем через защищённую консоль Supabase после регистрации
  трёх аккаунтов. Добавления администраторов через интерфейс нет. Замена —
  только владельцем вручную.
- Администратор не может быть забанен председателем. Администраторы не могут
  банить друг друга; снять администратора может только владелец проекта.
- Право администратора проверяется сервером для каждой операции, а не только
  скрытой кнопкой.
- Администратор может играть как обычный участник: садиться, писать, голосовать.
  Админ-инструменты не мешают игровому процессу.

### 4.6 Вход в админ-панель

- Панель не имеет видимой ссылки и не упоминается в подсказках.
- Скрытые способы входа: прямой маршрут `#/admin` и семь быстрых нажатий на
  эмблему (на телефоне — длительное нажатие 2 секунды). Скрытность — только
  дополнительный барьер, не замена проверке прав.
- После входа панель требует повторно ввести **собственный пароль аккаунта**.
  Сервер проверяет пароль и наличие пользователя в `admin_allowlist`.
- Неверный пароль — общая ошибка, ограничение попыток, задержка. Сессия панели
  короткая (30 минут бездействия), закрывается кнопкой «Выйти из панели».
- Обычный пользователь не видит панель и получает отказ от сервера даже при
  прямом вызове функций.

### 4.7 Админ-панель

Разделы:

1. **Зал** — количество мест от 12 до 80; изменение только при отсутствии
   открытого голосования; нельзя уменьшить ниже числа занятых мест; освобождённые
   места получают уведомление. Схема зала пересчитывается.
2. **Президиум** — назначить/снять председателя и сопредседателя, выбрать
   аккаунт; смена немедленно отражается у всех.
3. **Пользователи** — список участников, глобальный бан/разбан, смена роли в
   заседании (дипломат/наблюдатель/председатель), снятие с места, принудительный
   выход. Администраторов изменить нельзя.
4. **Пароль президиума** — установить новый; текущий не показывается; после
   смены — аннулирование разблокировок.
5. **Архив** — скрыть/удалить документ из публичного архива; содержимое
   снапшота не редактируется; действия аудируются.
6. **Аудит** — журнал административных и председательских действий: время,
   автор, действие, цель. Без паролей и содержимого шёпота.

### 4.8 Модерация: председатели и администраторы

- **Председатель (после разблокировки):**
  - управляет заседанием: слово, таймер, голосования, протокол;
  - удаляет сообщения общего канала и резолюции/правки в работе;
  - банит участника **в текущем заседании**: снимает с места и блокирует чат,
    слово, резолюции и голосование до разблокировки;
  - не может банить администраторов и других председателей;
  - каждое действие попадает в аудит и журнал заседания.
- **Администратор:** глобальный бан аккаунта (вход и все действия), снятие
  сессионного бана, управление ролями, архивом и залом. Глобальный бан
  отображается пользователю понятным сообщением.
- Удаление сообщения — мягкое: остаётся пометка «Сообщение удалено
  председателем»; исходный текст скрывается из интерфейса и API для обычных
  пользователей. Аудит хранит факт удаления, но не обязан хранить текст.

### 4.9 Приватность шёпота

- Шёпот видят только отправитель и получатель. Председатели и администраторы
  **не читают** личные сообщения через интерфейс; RLS не отдаёт их посторонним.
- В общем канале шёпот не появляется; в интерфейсе — отдельный раздел и явная
  метка «шёпот».
- Модерация содержимого шёпота не входит в публичные инструменты; при
  злоупотреблении владелец может действовать через защищённую консоль.

## 5. Зал заседаний

- SVG-схема сверху; сцена с фото зала, тёмным полом, флагами, часами и
  эмблемой-водяным знаком.
- **Количество мест задаётся заседанием** (`seat_count`, 12–80), по умолчанию 46.
  Места раскладываются дугами; при изменении числа схема пересчитывается,
  нумерация последовательная, свободные места видны пунктиром.
- Каждое место: кресло, стол, табличка с номером, аватар/инициалы, имя, страна,
  роль, статус слова. Свободное место открывает действие «Сесть».
- **Два кресла президиума** (`chair1`, `chair2`) с крупными читаемыми подписями:
  имена 16–18 px, роль — 12–13 px, высокий контраст. На телефоне подписи не
  уменьшаются ниже 14 px; при нехватке места используется отдельная карточка
  президиума над схемой.
- Сводка на столе президиума: голосование, последний лист, кворум.
- Легенда и инструменты масштаба; на телефоне зум вторичен, зал вписывается
  целиком.
- Блокировки: при открытом голосовании нельзя менять состав, места и президиум.

## 6. Пульт президиума

Открывается из шапки, левой панели или карточки председателя. Доступен только
назначенному председателю после ввода пароля президиума; администратору — без
пароля.

Содержит:

1. Состав президиума, кворум, предупреждение «вне кресла».
2. Регламент: крупный таймер, минуты, пауза/продолжить, сброс; по истечении —
   гонг и уведомление (автоматически выступление не завершается).
3. Слово: текущий выступающий, кнопка «Завершить», очередь с позициями, временем
   ожидания, кнопками «Дать слово» и «Снять». Очередь обновляется в реальном
   времени.
4. Голосования: активное голосование, черновики резолюций и правок, причины
   недоступности действий.
5. Модерация: удаление сообщений общего канала, удаление резолюций/правок,
   сессионный бан участника (кроме администраторов и председателей).
6. Документы: сформировать протокол; открыть лист/документ; скачать.
7. Порядок ведения — краткая памятка.

Все действия подтверждаются сервером, а не только скрытием кнопок.

---

## 7. Очередь слова

- Запрос доступен дипломату с местом; наблюдателям — нет. Один активный запрос на
  пользователя.
- Сервер ведёт очередь FIFO и хранит позиции. Клиент не является источником
  истины: после любого действия приходит подтверждение и актуальная очередь.
- Статусы: `waiting` → `speaking` → `done`, либо `cancelled`.
- Пользователь всегда видит: «вы N-й в очереди, примерно M мин», «ваше слово»,
  «выступление завершено»; кнопка «Снять запрос» доступна до начала.
- Председатель видит очередь, может предоставить слово, снять запрос, завершить
  выступление. Предоставление автоматически завершает предыдущее и запускает
  регламент; завершение останавливает таймер.
- Таймер считается по серверному времени (`ends_at`), поэтому не «зависает» при
  переподключении и не расходится между устройствами.
- Повторный запрос, запрос во время собственного выступления, запрос без места и
  запрос забаненным отклоняются с понятным текстом.
- Все операции идемпотентны (защита от двойного нажатия): повтор с тем же
  ключом не создаёт дубль.
- При обрыве связи интерфейс показывает «переподключение», очередь
  восстанавливается с сервера; потерянных запросов нет.
- События пишутся в журнал и тикер.

## 8. Резолюции и правки

- Резолюцию выдвигает дипломат с местом при отсутствии открытого голосования:
  номер (авто), тема, текст. Автор фиксируется снапшотом.
- Автор и председатель могут править черновик; председатель может удалить
  резолюцию, администратор — любую (с аудитом).
- Правки: отдельные голосования по одной, до общей резолюции; председатель
  открывает голосование, отозвать правку может автор или председатель.
- Открытие общего голосования: председатель в кресле, нет другого голосования,
  все правки решены, кворум соблюдён.
- Состояние синхронизируется между всеми участниками в реальном времени.

---

## 9. Голосования

- Открывает и закрывает председатель; одновременно не более одного.
- Снапшот присутствующих стран с правом голоса фиксируется при открытии; одна
  страна — один голос; голос можно менять до закрытия.
- Полоса голосования и крупные кнопки «За / Против / Воздержаться» доступны на
  телефоне; результат и живая сводка обновляются у всех.
- Закрытие: кворум и большинство; равенство — не принято. Лист итогов и документ
  автоматически уходят в архив.
- Во время голосования блокируются изменения состава, мест, ролей, новые
  резолюции и протокол; чат, шёпот и слово работают.
- Все проверки — на сервере; клиент не может подделать бюллетень или итог.

## 10. Чат и шёпот — главный функционал

### 10.1 Общий канал

- Один общий дипломатический канал заседания. Сообщение: аватар, имя, страна,
  роль, время, текст; удалённые — с пометкой.
- Realtime: новые сообщения приходят без перезагрузки; история подгружается
  порциями (50); прокрутка вверх подгружает ещё.
- Отправка: Enter — отправить, Shift+Enter — перенос строки; лимит 1200 символов;
  быстрые фразы у поля ввода.
- Оптимистичная отправка: сообщение сразу видно как «отправляется», затем
  «отправлено»; при ошибке — «не отправлено» и повтор. Дубли исключены
  клиентским id.
- Автопрокрутка только если пользователь внизу; иначе — счётчик новых сообщений.
- Чат не блокируется голосованием; это основное средство общения.
- Председатель (разблокированный) и администратор могут удалить сообщение.

### 10.2 Шёпот (личные сообщения)

- Личная переписка с любым участником заседания.
- Вход: кнопка «Написать шёпотом» в карточке участника/чате; отдельный раздел
  «Шёпот» рядом с общим каналом.
- В списке диалогов: собеседник, последнее сообщение, время, непрочитанные.
- В сообщении — явная метка «шёпот»; в общем канале его нет.
- Только отправитель и получатель. Третьи лица, председатели и администраторы
  через интерфейс содержимое не получают.
- Realtime, статусы доставки, счётчики, мобильная нижняя шторка.
- При бане шёпот с забаненным недоступен; история остается у собеседника, но
  новые сообщения блокируются.

### 10.3 Мобильный чат

- Отдельная вкладка нижней навигации; при новом сообщении — бейдж.
- Переключатель «Канал / Шёпот»; поле ввода закреплено над клавиатурой.
- Кнопки быстрых фраз — горизонтальная прокрутка, крупные.
- Открытие чата не перезагружает зал; уход из вкладки не теряет черновик.

### 10.4 Надёжность

- Supabase Realtime + повторная синхронизация при переподключении.
- Порядок сообщений — серверный (время + id); клиентские часы не влияют.
- Ошибки связи показываются ненавязчиво, без модальных блокировок.
- Таймаут подтверждения действия — 5 секунд, затем понятная ошибка и
  возможность повторить.

## 11. Документы

### 11.1 Лист итогов

- Формат 1200×675, экспорт PNG 2400×1350; тёмный ретро-терминал, сетка стран,
  цвета голосов, кворум, результат. Доступен промежуточный лист.

### 11.2 Документ резолюции

- A4 1240×1754, PNG 2480×3508, печать; бланк, эмблема, номер, метаданные, текст,
  правки, итоги, подписи, штампы. Заголовок печатается посимвольно
  (отключается при reduced motion).

### 11.3 Протокол заседания

- Формируется председателем в кресле при отсутствии открытого голосования.
- Номер `ПРТ-<год>-NNN`, состав, время, статистика, последние события.
- Просмотр на бумажном A4 с каскадом строк и печатной машинкой.
- Действия просмотрщика:
  - **Скачать PNG** — изображение A4 (2×);
  - **Скачать PDF** — готовый файл A4, многостраничный при необходимости;
  - **Скачать DOCX** — редактируемый текстовый документ с заголовками и таблицами;
  - **Печать** — системный диалог.
- Имена файлов: `PRT-2026-001.png`, `.pdf`, `.docx`.
- PDF собирается локально из отрисованных страниц (кириллица не зависит от
  шрифтов PDF); DOCX — из структурированного снапшота. Библиотеки лежат в
  `/vendor`, без CDN и без сетевых запросов.
- Те же кнопки доступны для документов резолюции.

## 12. Архив

- Экран `#/archive`: папки «Все / Листы итогов / Резолюции / Протоколы»,
  поиск, фильтры, сортировка.
- Записи неизменяемы, рендер из снапшота.
- Скачивание документов: PNG/PDF/DOCX/печать по типу.
- Администратор может скрыть/удалить документ из публичного архива; снапшот не
  редактируется; действие аудируется. Председатель удаляет резолюции в работе,
  но не переписывает архив.

## 13. Журнал, тикер, статус

- Журнал: события по времени, фильтры, поиск; административные и
  председательские действия помечены.
- Тикер: последние события; подсказки при тишине.
- Статус: связь, время заседания, президиум, кворум, голосование, счётчики.
- Всё обновляется в реальном времени; критические действия дублируются
  уведомлением.

## 14. Профиль, настройки, «Ещё»

- Профиль: имя, страна, аватар, флаг, роль, смена пароля, выход.
- «Ещё»: архив, журнал, помощь, настройки звука, выход; на десктопе — меню,

- Настройки заседания (название, дата, кворум, регламент) — председатель или

### 15.1 Текущая сборка (статическая, без Supabase)

Сейчас работает автономная статическая версия, сохраняющая состояние в браузере.
Она реализует интерфейс и правила из этого документа, но без общего сервера:

- аккаунты дипломатов: логин/пароль, PBKDF2-SHA256 (120 000 итераций, соль 16 байт);
  в `localStorage` только `{salt, hash}`;
- пароль президиума и пароли трёх администраторов также хранятся только хэшами;
  пароль президиума известен председателям и нигде в интерфейсе не показывается;
- скрытый вход администратора — 7 нажатий или удержание 1,6 с на эмблеме;
- три администратора заданы в `js/store.js`; смена их паролей — в админ-панели;
- схема зала 12–80 мест (`settings.seatCount`, по умолчанию 46);
- шёпот, очередь слова, модерация чата и резолюций председателем;
- экспорт: лист итогов PNG, документ резолюции PNG/печать в PDF/DOCX,
  протокол PNG/печать в PDF/DOCX;
- общий чат и настоящие роли требуют перехода на Supabase по разделам 15–17.
  До этого защита аккаунтов — от случайного доступа, а не от подмены кода.

- Ключевые ограничения: один аккаунт — один дипломат в заседании; уникальные
  место и страна с правом голоса; один открытый запрос слова и одно открытое

- RLS: чтение публичного состояния — авторизованным; шёпот — только участникам;

  автоматически; для переноса старых данных остаётся экспорт JSON.

## 17. API и правила

Клиент вызывает RPC/Edge Functions; права повторно проверяются сервером.

| Группа | Методы |
|---|---|
| Аккаунт | `auth.register`, `auth.login`, `auth.logout`, `profile.update`, `profile.changePassword` |
| Сессия | `session.state`, `session.update`, `session.newMeeting` |
| Зал | `seat.take`, `seat.leave`, `seat.move` |
| Слово | `speech.request`, `speech.cancel`, `speech.grant`, `speech.finish` |
| Чат | `chat.list`, `chat.send`, `chat.delete`, `chat.subscribe` |
| Шёпот | `whisper.list`, `whisper.send`, `whisper.read`, `whisper.subscribe` |
| Резолюции | `resolution.create/update/remove`, `amendment.propose/withdraw` |
| Голосование | `voting.open`, `voting.cast`, `voting.close` |
| Архив | `archive.list`, `archive.get`, `archive.createProtocol` |
| Президиум | `chair.unlock`, `chair.lock`, `chair.appoint`, `chair.release` |
| Админ | `admin.enter`, `admin.seats`, `admin.chairPassword`, `admin.chair.appoint/release`, `admin.users`, `admin.ban`, `admin.role`, `admin.archive`, `admin.audit` |
| Документы | экспорт выполняется локально из снапшота |

Формат ошибок: `{ ok: false, code, message }`; секреты и внутренние детали в
сообщения не попадают. Опасные операции идемпотентны и аудируются.

## 19. Анимации, звук, шум и читаемость

- Загрузочный глобус: вращение CSS, уважает `prefers-reduced-motion`.
- Появление экранов/модалок, бумага, штампы, печатная машинка — как в v1, но
  короче и без перекрытия контента.
- **Шум сильно ослабляется:** статичная мелкая зернистость, прозрачность
  0.02–0.03; зерно не накладывается на текст, чат, документы, формы и модалки.
  Убирается крупный `feTurbulence` поверх интерфейса; виньетка и свечение мягче.
- Контраст основного текста — не ниже 4.5:1; вторичного — не ниже 3:1.
  Обязательная проверка на всех поверхностях: чат, документы, панели, кнопки,
  таблички зала.
- Гонг WebAudio: голосования, регламент; mute сохраняется. Звук не блокирует
  интерфейс и разблокируется первым действием пользователя.

## 20. Крайние случаи

- Нет сети: загрузчик показывает состояние, приложение не притворяется, что
  сообщение отправлено; после восстановления связи — синхронизация.
- Обрыв во время выступления: таймер считается от серверного `ends_at`.
- Пользователь забанен: активные действия блокируются, понятное уведомление;
  глобальный бан закрывает вход.
- Попытка открыть админ-панель без прав: отказ сервера, без раскрытия списка
  администраторов.
- Неверный пароль президиума: общая ошибка, лимит попыток, без подсказок.
- Смена пароля президиума аннулирует разблокировки.
- Уменьшение числа мест ниже занятых запрещено; занятые места не «исчезают».
- Открытое голосование блокирует изменение состава, мест и ролей.
- Шёпот третьему лицу недоступен даже при прямом запросе к API.
- Удаление сообщения не ломает историю: остаётся служебная пометка.
- PDF/DOCX/PNG проверяются на кириллицу и многостраничный протокол.
- Локальные данные v1 не смешиваются с онлайн-состоянием.

## 21. Тестирование и приёмка

Обязательные проверки перед сдачей:

1. **Аккаунты:** регистрация, вход, выход, смена пароля, занятый логин, слабый
   пароль, ограничение попыток.
2. **Роли:** администратор (ровно 3), председатель, дипломат, наблюдатель;
   администратор играет как обычный участник; обычный пользователь не может
   вызвать админ-функции.
3. **Секреты:** в собранном фронтенде нет паролей, хэшей, `service_role`, списка
   админов; anon-ключ не читает приватные таблицы и шёпот.
4. **Пароль президиума:** не отображается и не подсказывается; неверный ввод
   блокируется; смена аннулирует разблокировки; председатель без разблокировки не
   управляет заседанием.
5. **Чат:** отправка, порядок, реальное время, повторная отправка, удаление,
   быстрые фразы, мобильная клавиатура, непрочитанные.
6. **Шёпот:** доставка только двум участникам; третье устройство не видит
   содержимое; метка, счётчики, мобильная шторка.
7. **Слово:** позиция в очереди, отмена, предоставление, завершение, таймер,
   переподключение, отсутствие зависаний и дублей.
8. **Админ-панель:** скрытый вход, повторный пароль, места 12–80, смена пароля
   президиума, назначение председателей, бан/разбан, роли, архив, аудит.
9. **Мобильные:** 360–480 px, нижняя навигация, вкладка чата, все действия,
   отсутствие горизонтальной прокрутки, safe-area.
10. **Загрузчик и читаемость:** глобус, текст, reduced motion; шум не мешает
    чтению; контраст.
11. **Документы:** протокол PNG/PDF/DOCX/печать, кириллица, многостраничность;
    лист и документ резолюции.
12. **Регрессия v1:** резолюции, правки, голосования, архив, настройки.

Среда проверки: обычный браузер и мобильная эмуляция; визуальная приёмка
обязательна в Chrome/Edge и на реальном телефоне.

## 22. Публикация и настройка (GitHub Pages + Supabase)

**Ничего не публикуется без отдельного разрешения владельца.**

### 22.1 Подготовка Supabase

1. Создать проект Supabase (регион ЕС).
2. Применить SQL-миграции из `supabase/migrations`: таблицы, RLS, функции,
   аудит. Файлы миграций не содержат паролей и реальных списков администраторов.
3. В защищённой консоли/скрипте задать:
   - стартовый пароль президиума — один раз, сразу в bcrypt-хэш;
   - трех администраторов — после регистрации их аккаунтов добавить их `user_id`
     в `admin_allowlist`.
4. Настроить Storage-бакеты аватаров и флагов с политиками.
5. Edge Functions: `register`, административные операции, сброс пароля;
   `service_role` хранится только в секретах функций, не в репозитории.
6. Проверить RLS-тестами: anon-ключ не читает приватные данные, чужой шёпот и
   админ-таблицы.

### 22.2 Публикация фронтенда

1. В `config.public.js` указать только `supabaseUrl` и `supabaseAnonKey`.
2. Загрузить статические файлы в GitHub-репозиторий.
3. Settings → Pages → Deploy from branch → `main` / root.
4. Проверить на телефоне и десктопе: вход, чат, шёпот, слово, админ-вход.
5. `server.js` в продакшене не используется; это локальный помощник.

### 22.3 Дисциплина секретов

- В репозиторий **не коммитить**: `.env`, `service_role`, пароли, bcrypt-хэши,
  временные пароли, реальные списки администраторов.
- Пароль президиума и пароли администраторов передаются владельцем вне сайта.
- Anon-ключ публичен по назначению; защита — RLS и RPC.
- При подозрении на утечку: сменить пароль президиума, отозвать сессии,
  проверить аудит.

### 22.4 Автономный HTML

`tools/build-single.js` может собрать один HTML для демонстрации интерфейса.
В v2 это **только офлайн-демо**: без сервера нет общих аккаунтов, реального чата,
шёпота и банов. Для беттастеров основным считается онлайн-фронтенд после
настройки Supabase.

## 23. План внедрения после подтверждения

1. Зафиксировать архитектуру (Supabase) и получить три логина администраторов.
2. Схема БД, RLS, функции, Storage, аудит; удалить видимый код администратора.
3. Регистрация/вход, профиль, роли, привязка аккаунта к дипломату.
4. Realtime-чат, шёпот, мобильная вкладка чата, статусы и переподключение.
5. Серверная очередь слова, таймер, исправление зависаний.
6. Админ-панель, пароль президиума, баны, модерация, архив.
7. Динамические места, крупные подписи президиума, загрузочный глобус,
   ослабление шума, упрощение первого экрана.
8. PNG/PDF/DOCX для протокола и документов.
9. Мобильная приёмка 360–480 px, тесты безопасности, README, пересборка
   офлайн-демо.

### 23.1 Открытые решения

- Три логина администраторов (владелец и два человека) — нужны до настройки
  allowlist.
- Баны председателей: по умолчанию сессионные; глобальные — только
  администратор.
- Шёпот: только участники, без чтения председателями и администраторами.
- Старые локальные данные v1 в онлайн не переносятся автоматически.

## 24. Что остаётся от v1
